## 恢复案例建设后的流程

1. 先确认真实用户、任务、起始项目、输入、必需条件和成功判据。
2. 先检索候选再决定采用路径，保留排除理由和未核实项。
3. 分别记录来源事实、设计建议与实际运行结果。
4. 让开发或研究过程使用资料包，记录补查、材料错误和遗漏。
5. 在相同模型、输入和环境下，对照普通搜索/文档工具与增加 FieldToFit 的效果；隔离上下文。
6. 保留产物和失败情况，并由真实目标用户验收；一次样例通过不推广为普遍收益。

## 每份记录需要包含

| 部分 | 内容 |
| --- | --- |
| 任务 | 需求来源、输入、输出、必需条件和成功判据 |
| 材料 | 检索范围、候选、版本、原文位置、采用/排除依据、缺口 |
| 执行 | 环境、依赖、操作步骤、输入标识和实际产物 |
| 结果 | 每项判据通过/失败/未验证，原因和实际输出 |
| 边界 | 未覆盖输入、用户效果、版本变化和后续复验要求 |

研究、学习任务按其适用产物验收：引用、解释、实验设置和学习结果不能由代码样例替代。源码检查通过、文档齐全、技术运行通过和产品价值验收是四种不同结论。
