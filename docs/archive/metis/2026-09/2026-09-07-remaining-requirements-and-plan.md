## 3. 建议方案

### S1 每日采集与处理闭环

将“发现 → 获取原文 → 整理事实 → 生成人类内容 → 发布”作为有独立状态的日处理流程。为每个来源保存增量位置、分页位置及未完成记录；超时或单个来源失败不会把其余来源记为完成，下次日任务继续补齐，保留管理端手动重试。

补足国内外官方团队、模型、数据集、垂直应用及研究来源。现有 arXiv/HF 等以最近固定数量为主的采集，改为按更新时间窗口翻页并核对遗漏；历史补采独立记录范围。不可访问的来源展示缺口和可用官方入口。

验收建议：完成连续 3 个日周期观察，检查新增、修订、失败、恢复及部分成功；页面分别显示“来源检查完成”和“内容整理完成”，不承诺未经测量的覆盖率。

### S2 事件、对象和分类整理

分别维护对象身份、版本发布事件及来源报道；用仓库、论文 ID、官方域名、版本等确定关系，同名或语义相似只作为候选。一个事件保留多份报道，一次版本更新保留独立事件。疑似重复进入审核队列，允许人工合并、撤销及拆分。

主题、对象类型、任务能力分别分类。关注度记录来自哪里、何时观察及变化，作为发现信号；任务排序另外依据条件和证据。

验收：同一发布的多篇报道能归并，两个版本不会混为一条；同名无关资源不误合并，低相关资料不占据主题列表。

### S3 原文与完整档案

按来源类型获取正文、README、版本文档、模型/数据卡、论文 HTML 或可解析 PDF；保留具体版本、章节、页码或段落定位。自动提取任务用途、输入输出、部署、语言、费用、许可证、硬件、限制等字段，每项附证据。表格和公式解析不足时明确标注。

材料存储与人类摘要分开：AI 按需读原文和事实，网页按层次展示。自动处理只在相应字段具备依据时提高完整度；相互冲突的事实并列保留，不用最新抓取覆盖分歧。

验收：抽查关键条件能定位到相应版本原文；摘要、部分正文、完整材料的状态正确，缺失条件保持未知。

### S4 给人阅读的信息整理

从同一组事实输出中文和英文：一句话说明、关键变化、适用人群、重要性理由、限制及原文入口；长原文进入深读层。新品保持专有名称，其他内容提供可读解释。

基于归并后的事件制作每日重点和分类快讯，保留历史日期入口。重要性由实际变化、证据质量、任务相关性及关注信号解释，不仅依据时间或星数。素材不足时允许减少条目。

验收：新数据自动形成双语内容，人能快速判断是否继续阅读；关键事实两种语言一致，所有重点可回到来源。

### S5 任务检索与条件对比

先将自然语言目标拆成任务、输入输出、必需条件与偏好，允许用户调整解析结果；检索结合关键词、能力标签和语义候选，再按有来源的条件核对。语义召回作为增强能力，无模型配置时仍保留基础检索。

为费用、显存等建立带单位和适用条件的数值比较，为平台、语言、许可证等建立规范化字段。结果明确满足、不满足、未知，显示完整候选分页及匹配理由。热度、近期维护和任务适配分别展示。

验收：同一意思的不同说法能找到合理候选；预算或硬件条件不会因字符串匹配而误判，未知不会被当作满足。

### S6 面向任务的资料包

输入目标、现有基础/环境及约束，输出候选、采用依据、具体材料、行动步骤、成功判据和待核实项。工程任务分别支持直接使用、基于开源扩展、自行设计及混合采用；研究、复现、学习任务使用各自的产物结构。

资料包可以由 Metis 整理，也可以由调用方 AI 依据 MCP 返回的材料组织。Metis 负责提供可靠材料和明确结构；步骤引用相应版本文档和实际案例，不能用固定提示语冒充任务方案。

验收：选定任务能产出带依据的方案、阅读材料或最小实践；用户与 AI 可继续读取细节，导出保留出处及适用条件。

### S7 研究与学习资料

论文详情增加研究问题、方法、实验、贡献声明与局限；关联官方实现、第三方复现、模型、数据和基准并标明关系来源。实验比较按任务、数据版本/划分、指标、模型、硬件设置对齐，不可比的结果明确分开。

按学习或组会目标组织入门解释、前置知识、阅读顺序、方法比较及最小实验；输出专题 Markdown 和有依据的引用信息。分别标注最小例子、缩小实验和完整论文复现。

验收：组会资料的关键观点可核查，阅读路径与目标相关，比较不跨实验设置宣布优劣。

### S8 无账户的关注更新

浏览器保存关注对象、主题及上次查看位置，公开查询接口提供相应的增量变化。“关注更新”展示新增能力、版本变化、条件变化和资料修正，支持已读状态及历史。主题关注展示实际更新，而不仅是跳转筛选页。

全部基于本地保存和公开读取，不要求注册或发送邮件。清除浏览器数据会清除本地关注和阅读位置，页面明确保存位置。

验收：再次打开能看到关注范围内的变化，同一报道不重复提醒；账户仍为待开放。

### S9 管理、模型配置与反馈处理

将原始 JSON 修改补充为事实、分类、来源、关系及验证记录的编辑表单；提供待整理、缺证据、冲突、失败等处理队列，修改留下依据和历史。来源支持可视化配置，周期固定 1 天。

统一生成模型的地址、模型名和凭证配置；将分类、提取、翻译、简报等步骤接到同一适配层，记录所用模型和整理版本。用两种实际配置核对输出结构，失败可恢复，无凭证时显示待整理且保留基础服务。

反馈增加待处理、已处理及关联资料/任务记录，区分“有兴趣”“已部署”“完成任务”“再次使用”；只记录用户主动提供的信息。

验收：主要内容维护无需编辑 JSON；模型切换不改变公开数据格式，反馈能追踪到修正或任务结果。

### S10 真实案例与自动验证

将原有 12 个场景模板绑定具体任务、输入和成功条件，每类用户 3 个。保存资料版本、环境、执行步骤、产物、实际结果和局限。先建设覆盖四类用户的 4 个具体样本，再扩充其余案例和资料包。

对适合自动运行的最小示例使用指定依赖和受控执行环境，设置资源、时间及网络范围；按 1 天检查变化，对受影响案例执行检查。阅读和判断类任务保留人工验收，不以接口测试代替实际任务成功。

用同样模型、输入与环境，对比基础搜索文档流程和加入 Metis 材料后的任务结果，判断信息是否真正减少错误或缺失。失败也保留结果。

验收：12 个场景都有实际产物与判定；未执行、失败与通过分开，旧版本成功不自动沿用到新版本。

### S11 MCP 与自行部署验收

沿用现有 HTTP/stdio 接入，随资料包、研究材料及增量过滤补齐访问能力。在实际日常客户端完成“查询—读依据—形成产物”的演示，覆盖四类场景，记录客户端版本、配置及结果。

在干净环境验证源码和容器启动、持久化、重启、每日采集、页面、导出与 MCP；同时检查没有生成模型凭证时的基本可用性。实际部署后验证稳定链接及页面描述。

验收：陌生使用者按文档可自行启动，并在一个完整任务中拿到可核查产物。生产部署验证单独记录，不能以构建文件存在作为通过。

## 4. 内容建设目标与顺序建议

200 个资源、100 篇研究资料、60 份完整任务资料包、12 个案例继续作为先前提出的建设目标；这些数量不代表全部都已核验或每条都必须人工维护。优先围绕实际任务补齐证据，不能用条目数量代替可用性。

建议依赖顺序：

1. 打通 S1/S3/S4/S9 的每日采集、原文、双语整理与处理状态，同时建设 S2 的归并和分类。
2. 使用具体样本完善 S5/S6/S7，完成四类用户各一个可核查任务；案例标准从这一步开始使用。
3. 补齐 S8、S10、S11，扩大资料包与案例覆盖，完成日常使用及部署验收。

第一组建议样本：工程师的本地中文 PDF 处理、研究者的同任务两篇论文比较、研究生的官方基线缩小复现、学生的普通电脑最小 AI 实践。这些是建议验收题，尚未代表真实用户已经提出或验证了它们。

第一批可见成果应包括：读起来清楚的中文每日信息、条件和出处完整的重点档案，以及能用这些资料完成的实际任务产物。
