# 平台验收与正式版门槛

P3 · 2026-09-11。适用 [20 项 REQ / 81 个子 REQ](requirements.md)。2026-09-09 的[平台实现检查](../validation/2026-09-09-platform-foundation.md)记录当前局部验收；当前应用软件版本 v1.0.3；该版本号不等于以下全部正式运营门槛均已完成。

## 如何登记完成

每个子 REQ 记录：完整新编号、实现提交、环境、数据/材料修订、输入和操作、预期、实际结果、通过/失败/未执行、证据位置及剩余限制。文档设计、代码检查、内容审核、实际客户端、真实运行与用户反馈分别登记。

父项只有全部子项达标才完成。需要外部环境而未执行的保持待实测，不以模拟结果补齐。新功能改动按影响做行为检查；文档检查链接、编号和覆盖；功能改动另做行为及页面验证。

## P3 内容与展示补充门槛

1. 首发本期重点、动态、资源逐条获确认；确认名单与真正发布批次可对应，草案不自动入库。
2. 近期动态与资源档案两区可读；每点来源观点与 FieldToFit 解读分开，每个动态关联正确公司/产品/版本；不同日期不混用。
3. 资源近期关注有实际来源/观察窗口；长期价值有明确理由，不把星数等同能力或本地实测。
4. 来源页两表反映真实覆盖；所有检查周期 1 天；计划中的公司不能展示为已采集成功。
5. API/MCP 与网页对相同记录、原文、引用、更正和撤回保持一致。

目录、双区布局与动态读取已实现；来源表、完整材料自动维护等仍按子项状态验收。

## 必查边界场景

| 场景 | 预期 |
| --- | --- |
| 来源失败、模型不可用、没有新增 | 三者状态分开；已有已发布资料仍可读取；旧日期不变成今天新增 |
| 大文档跨段、材料仅链接、扫描 PDF | 可续读已存文本；仅链接与解析缺口明确，不返回“全文完整”的假结论 |
| 同对象新版本、同名不同对象、重复报道 | 身份正确，变化不重复，旧依据可追溯 |
| 冲突、纠错、撤回、精选退出 | 各状态有对应行为；两端与导出一致；游标能读到变化 |
| 无注册、错误令牌、外部指令式原文 | 可公开取材；权限错误可辨；只读接口不发生安装或管理写入 |
| 旧详情、旧 MCP 工具与本地收藏 | 有兼容结果或明确迁移说明，不静默丢失已知 ID |
| 本机服务交给云端 AI | 明确可达边界，提供实际可复制材料而非只给不可达链接 |

## Pending 与不作为门槛的事项

- AI 应用案例 pending，包括技术文章/论文的解释图、流程图方向。没有恢复授权前不实施，不拿旧 PDF 金额样例宣传本轮价值。
- 公开注册、登录和同步待开放。完整任务规划、工具比较排名、学习路线、案例执行和通用代码沙箱不属于本轮平台验收。
- 真实模型服务要验证用于整理的主配置；第二供应商成功切换另如实记录。若未实测，不声称已支持所有供应商；人工审核/导入流程仍须可用。
- 容器与 Turso 只有在宣称正式支持时才列对应环境必验；未测方案必须明确实验性，不能用本地 SQLite 结果代替。

历史案例验收规则见[调整前快照](../archive/metis/2026-09/2026-09-08-before-platform-acceptance.md)，技术记录见[验证索引](../validation/README.md)。案例恢复需另行对齐，其成功不替代当前平台门槛。
