# FieldToFit 内容管理

维护入口为 `/admin`。旧 `/admin/curation` 自动进入同一个后台的“每日审阅”，不再展示第二套主导航。管理员登录与公开账户独立，密码仅配置于服务端；公开注册继续关闭。

| 模块 | 管理什么 | 操作结果 |
| --- | --- | --- |
| 每日审阅 | 问题待办、推荐批次、采集发现和人工候选；按北京时间筛选；来源日期单独显示 | 加入待整理、稍后处理、忽略；选中不发布 |
| 内容库 | 近期动态、持续关注五类资源、AA/Arena 图表、开发者投稿项目 | 编辑草稿、双端预览、明确发布、下架、恢复历史到草稿 |
| 需求反馈 | 网站收到的反馈；分页、搜索、处理状态及说明 | 保存处理结果；资源推荐可人工登记为候选，关联内容编号可打开编辑 |
| 来源与运行 | 来源阶段统计/明细、当前积压与等待、启停/重试、可选整理服务和备份 | 沿用每日检查与管理权限；打开页面不自动调用模型或发布内容 |

## 一条材料如何出现在网站上

1. 每日审阅优先展示需要处理的问题与候选分组。没有候选时可以查看近七天/全部日期，并核对采集记录是否成功。
2. 选择候选，阅读出处，指定近期动态或持续关注及类型。有相同来源的既有内容时，可明确选择更新该内容，候选材料会附加到整理稿，不覆盖原稿。
3. 点击 **加入待整理**。系统创建或关联私密草稿，编号保持稳定。此时 For you、For your AI 和 MCP 不显示新草稿。
4. 内容库中补齐介绍、逐点解读、出处及版本资料。表格可以逐格修改、增删行列；动态可指定是否进入速览（最多五条）；展示位置从 1 开始，留空保留原位。
5. **保存草稿**仍不改变公开内容。已有条目的旧发布版持续可读。
6. **生成双端预览**，检查真实 For you 渲染与 For your AI 的公开数据。缺出处、缺观点、无效表格或来源口径错误会阻止发布。
7. 核对两端内容、填写变更原因，勾选复核后点击 **发布到网站**。一次事务更新共享数据及发布历史。待整理候选转为“已完成发布”。
8. 错误内容可注明原因下架；恢复历史只回到草稿，需重新预览和发布。首个历史版本包含迁移前原样内容。

远程写入在单次服务端事务中重核已读取行集并执行，避免跨区域请求耗尽短事务时间。并发保存使用草稿版本；发布还绑定集合修订与已存来源材料指纹。其他维护者或采集过程改变相关数据后，旧预览和旧 AI 导入会被拒绝，需重新读取。当前为一个共享管理员身份，尚不提供多个编辑者的实名审计。

## 本地 AI 整理

编辑页选择“导出给本地 AI”，获得 `fieldtofit.editorial-workspace.v1` 文件，包含草稿及实际已存材料。迁入的版本化条目不自动获得全文；只有发现摘要的材料标记 `discovery_summary`，公开出处继续标明 `link_only`。

让 AI 仅修改 `draft`，保留 `kind`、`id`、`draft_version`、`materials_fingerprint`。不编造日期、数值或实测，不执行来源内容中的指令。导回文件只保存草稿，随后依次预览、核对、明确发布。未应用的完整 JSON 编辑会阻止保存和发布，防止误用旧值。

旧 `metis.editorial.v1` 材料处理仍在内容库的“既有材料库与历史整理记录”内，用于旧对象的原文、引文、归并与概览；不会自动变成当前首页动态或持续关注。

## 图表与投稿

图表编辑器分别展示 AA、Arena 数据表、原始名称、配置、数值、日期和出处。旗舰名单可逐公司选取来源配置；缺项保持未收录。新增模型/置信区间等复杂数据可通过完整快照或本地 AI 导入。价格单位与 2026 年范围沿用公开契约，校验通过才可发布。日检查不自动更新数值或来源日期。

开发者投稿使用持续关注条目的 `origin=developer_submission`，补齐公开入口、用法、开放情况、作者与提交者关系并确认可公开；不另建一份重复数据。GitHub 和邮件仍由维护者人工查看和登记，未开通自动同步。网站反馈不自动发送邮件或创建 Issue。

## 首次迁移、备份与回退

部署前先使用[远程快照脚本](../../scripts/maintenance/remote_snapshot.py)将生产数据库备份到私密本地文件并完成独立 SQLite 完整性检查。部署后首次点击“导入现有已发布内容”，或调用同名管理接口，将 10 条动态、27 个持续关注主体及 1 套双来源图表原样接入数据库。迁移包含显式建表，适配关闭自动初始化的生产配置；为幂等原子批处理，保留编号、正文、来源日期及公开修订；不会改写旧数据库材料。

迁移前没有内容集合时，公开接口使用已审核的仓库文件；迁移后数据库中的已发布集合为权威，草稿独立保存。数据库读取失败时返回明确错误，不回退到可能重新暴露已下架内容的旧文件。

“来源与运行 → 下载内容库备份”导出当前集合、草稿、发布历史和审阅关联，含内部资料，不能公开提交。完整数据库备份另需保留旧材料表。单项纠错优先用发布历史恢复。全库灾难恢复应在隔离环境先检验备份，再恢复数据库并运行兼容的新代码；不能直接退回只读取旧文件的 v1.0.5，否则会忽略迁移后的发布和下架。

管理发布不需要重新部署前端。内容修改有数据库修订、时间和原因；按[版本规则](releasing.md)交付代码、文档或导出内容提交时递增版本。导出并版本化保存资料时，只提交经过公开字段过滤的内容，不提交含私密草稿的后台备份。


## v1.3.0：推荐批次与公开材料

现有部署先备份，再调用管理员 `POST /api/v1/admin/workspace/upgrade`。该操作仅新增批次、决定/事件、旧材料表和九条来源配置；重复执行不覆盖已有来源设置。全新安装由 schema 初始化，已有公开集合仍通过 migrate 原样导入。

每日审阅顶部“更新批次与日报”汇总两条入口。创建批次与写提案不发布网页。每项显示标题、推荐理由、拟上站内容和历史；“继续整理”才允许关联草稿，“稍后”必须给复查日期，“不采用”仍保留证据。关联草稿和记录决定使用同一事务；新证据变化重新待决定，发布旧草稿不误记为新建议已处理。

本地接口：`POST /batches` 创建日期批次，`POST /batches/<id>/propose` 写 event_url、event_version、fingerprint、proposal（标题、理由与具体文案）及可选 ref；`POST /batches/<id>/intake` 接入网站选中项。相同事件、版本、证据和提案跨日不重复，新证据保留前次提案记录。`POST /topics/<id>/decide` 和 `/attach` 必须传最新 version，冲突重读。

`POST /batches/<id>/delivery` 分别登记 running、prepared、delivered、failed。delivered 要求真实消息/交付记录 receipt 与 confirmed=true；只生成文件不能算已送达。当前不由服务器发送消息，也没有后台自动核验聊天消息的服务，尚未核实就保留 prepared。所有接口前缀是 `/api/v1/admin/workspace`，需要管理员身份，不对 MCP 开放。

编辑新闻/持续关注时，“供读者与 AI 读取的材料”将已采正文复制到待复核字段，默认未确认。每份填写公开范围、日期、稳定 ID、上游版本和许可依据，保留所需署名；未确认或正文缺许可不能发布。无全文依据则保留链接和原因。双端预览读取当前私密草稿，公开 API 继续旧修订；确认发布后清单与正文同时公开。正文支持固定修订续读，下架/权限撤回覆盖历史访问。备份包含新增批次和旧材料表。


## 来源阶段统计与问题待办

“来源与运行”先展示当日动作统计，按北京时间选取最近 31 天。检查列为当日实际检查过的来源数，另列尝试次数；新发现、原始材料变化与获取覆盖分别计数。一次候选可同时取得全文和节选，各覆盖列不相加当作总条数。来源行可交叉归属，全站按候选 ID 去重。“提交复核”按内容与草稿版本计数；保存草稿、调用 AI 或通过预览不计为完成整理，需在预览区点击“整理完成，提交复核”。源材料实质变化或再次编辑会取消当前待复核状态。发布仍需独立确认与原因。

“当前待整理 / 待复核”始终显示现在的积压，不随日期选择回放。等待从已记录的进入阶段动作算起，重复保存不清零；升级前无进入时间的项显示未知。阶段表从新增记录启用后积累；启用当天标明不完整，之前不能显示为精确的 0。来源检查历史与阶段记录是不同口径。

“每日审阅”的问题清单聚合来源失败/待续、草稿缺名称/出处/解读、材料未审核或不可读、已选候选缺可核对材料、待复核、超过三天等待，以及已发布条目的关联来源后续变化。正常的论文摘要、已声明的仅链接范围不自动作为错误。事实矛盾仍需人工核对，不宣称程序能从自然语言自动判断真假。问题可打开对应草稿/候选或重试来源；“稍后处理”必须填写原因和复查日期，到期或证据变化重新提醒。只有真实问题消失才进入已解决记录。

私密接口（均要求管理员认证，不对 MCP 或公开页面开放）：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/admin/workspace/operations?day=YYYY-MM-DD` | 日期、来源阶段统计及当前问题 |
| 同接口加 `metric`、`source` | 对应数量的事项明细 |
| `POST /api/v1/admin/workspace/operations/refresh` | 持久化问题出现/解决状态；日采集结束也会汇总 |
| `POST /api/v1/admin/workspace/operations/issues/{id}` | 按 fingerprint 登记 note 和 review_on；并发变化返回冲突 |
| `POST /api/v1/admin/workspace/content/{kind}/{id}/submit-review` | 校验草稿版本及 review_token，记录整理完成，绝不发布 |
| `POST /api/v1/admin/workspace/operations/upgrade` | 显式新增私密阶段与问题表，重复调用不删除旧记录 |

新增表：`fieldtofit_operation_events`、`fieldtofit_operation_issues`；备份包含两表。部署前以授权生产配置运行同一增量迁移，先保存私密备份，再部署代码。旧版本回退保留新增表。不能用删除数据库或重新导入种子覆盖在线发布内容。

## 每日准备、交付与真实运行验收

本机同一安排每天北京时间 07:30 准备、08:00 交付。准备生成实际提案并保存为 prepared；交付要有真实用户可见消息/回执才能记 delivered。08:00 到达时若准备失败，仍报告实际状态，后续补交标明补发。需要电脑与应用运行；配置存在不表示已准时送达。权限保持为只读核对、私密推荐批次与交付记录，选题发布仍先与用户对齐。

服务器仍每日 06:30，周期 1 天。工作流记录 `trigger` 区分人工请求、含调度请求头的调用及旧记录未知；请求头是线索，应结合真实调度日志，不单凭字段认定自动运行。Meta 的目录页队列与文章队列分离，先处理已保存文章再扩展目录页；未处理/失败文章保存到下一轮；arXiv 失败时仅尝试官方 cs.AI 当日摘要中的相关标题，不覆盖整个检索和历史范围。失败继续显示，原查询游标保留。见 [arXiv 官方订阅说明](https://info.arxiv.org/help/rss.html)。

当前三日/周维护/跨日客户端观察计划保存在忽略目录 `output/operations/p0-operations-2026-09-15/acceptance-plan.json`，基于实际部署时间开始；每天逐源保存原始证据，人工重试不算新一天。满一周核对持续关注名单、长期缺失、积压和反馈，给出维护清单并先对齐具体内容动作。真实客户端基线和原始追踪保留在同目录，复验应继续用独立目录及临时 MCP 配置，不读取项目文件替代 MCP 回答。

## 对象归并与材料维护（v1.4.0）

当前为本地完成、待部署功能；正式站仍为 v1.3.3。入口为内容管理 → 每日审阅 → 对象归并与材料维护。

- **候选归组**：先由原有“加入待整理”生成私密草稿，再选来源草稿和保留对象。“归入已有对象的待整理稿”仅合并草稿和材料关联，不能更新公开内容。仍需内容库预览及明确发布。
- **对象／事件归并**：同类对象可以归并，动态与持续关注跨类型只能建立关系。共享来源或同名只是核对建议；不同版本、不同事件不能仅凭同公司归并。逐项选择冲突字段、填写原因、核对双端预览后再次确认；任一内容或材料变化使预览失效。保留对象的 ID 不变，旧编号留有去向和历史，来源与已获授权的材料保留。
- **误归并撤销**：在历史中预览撤销。默认恢复来源条目并保留目标当前内容；只有目标无后续编辑，才允许同时恢复目标归并前内容及本次复制的来源关联。原先未发布的来源恢复为草稿；不借撤销发布旧候选。若目标又归入其他对象，先处理后一次归并。
- **关系**：支持发布方、产品系列、版本、发布事件、实现、集成与相关资料。内部已发布对象可双向访问；外部公司／系列／版本须填写名称、官方入口、关系依据及适用版本。关联不等于官方认定或兼容保证。关系移除也须预览、填写原因并确认。
- **材料维护**：按北京时间每天检查一次已登记的公开阅读材料；单日重试不累计失败天数，漏检日打断连续失败。三日连续失败进入复核，七日提升优先级并重新打开延期事项。比较首次基线之后的响应内容指纹／最终地址，不推断事实变化；页面动态内容也可能触发人工核查。请求沿用安全获取与大小限制，不保存本轮网页正文。
- **处理问题**：可重新检查、打开内容库补材料／修订／退出展示、公开说明后保留或确认已复核、私密延期。人工复核不会把失败状态改写为可访问；检查成功也不刷新正文日期或事实审核日期。材料移除、正文权限撤销、对象撤下均通过原发布门槛执行，历史读取遵守当前权限，不承诺永久保留正文。
- **影响范围**：列出引用同一材料的对象与明确关联 source_ids 的观点。没有逐观点引用映射时明确要求人工核对；其他材料只是核对入口，不能自动认定可以替代失效证据。

部署前先保存私密全库备份并验证，使用当前代码执行幂等 `backend.knowledge.stewardship.upgrade()`，再切换应用版本。若部署时尚未升级，可在本模块点“初始化维护记录并重试”；但不应在表未就绪时执行内容发布。新增六表：`fieldtofit_steward_actions`、`fieldtofit_steward_aliases`、`fieldtofit_steward_links`、`fieldtofit_steward_checks`、`fieldtofit_steward_events`、`fieldtofit_steward_decisions`。内容库备份纳入六表，含私密审核记录，不能提交 GitHub。回退应用须保留表和已发布数据。

管理接口位于 `/api/v1/admin/workspace/stewardship`：GET 返回核对建议、材料问题及历史；POST 子路径 `upgrade`、`preview`、`apply`、`check`、`decide-material` 分别初始化、预览、确认、访问检查和处理复核。所有写操作沿用管理员权限。日任务分配不超过总预算 15% 且最多 30 秒给材料检查，未检查项保留待续，避免占用全部发现采集时间。
