# OpenAI／Anthropic 更新专题

对应 [REQ-26](../../FieldToFit-PM.md#req-26)。两个长期专题独立展示，沿用已有新闻记录与CMS；v1.19.0已于2026-11-09部署，实际范围见[验收记录](../validation/2026-11-09-company-updates.md)。

## 展示与归属

- 首页每家最新3条，展开最多10条，完整专题保留全量并每页20条。每条为时间、标题结论、既有已审摘要、完整记录与原始出处。不要为了满足展示数量制造更新。
- `/for-you/openai`、`/for-you/anthropic`及对应英文路径提供产品、月份、关键词筛选；筛选和页码写入URL，进入D-详情后可以返回阅读位置。源链接继续保留。
- 新闻组织字段精确为`OpenAI`或`Anthropic`才归入对应专题；仅在第三方正文中提及厂商、合作方混合组织名不会自动收录。归属有歧义时先核对并走原记录修订，不以关键词替代事实。
- 首期事件日期从2026-11-02起；复用已审记录，不创建第二份内容。日期优先采用已审Codex原事件日期，其次event_date，最后source_published_at；日期不足或未来日期不进入专题。已有精确且带时区的原帖时刻才换算北京时刻，只有日期则不推造时刻。原动态可读性不因专题日期边界而改变。
- 产品筛选依据既有记录的产品名及Codex专题归属，保守归入Codex、ChatGPT／Work、Claude Code、Claude、模型与API或其他更新；是导航分类，不构成新的能力／范围声明。研究与其他公司公告仍可在其他更新中查看。
- 排序为原事件日期／已有精确时刻及稳定ID，不使用修订日或抓取日置顶。首页、完整页、HTML、API与MCP从同一集合生成。
- 历史专题默认折叠。原`/for-you/codex`及日期／Day深链接保持，旧首页Codex锚点继续直达完整日志；98条历史记录不迁移、不删除、不重写日期。

## 每日搜索、整理与发布

沿用同一私密晨报07:30准备／08:00交付，不恢复已结束的22:00／22:30日程，不建立另一套自动出刊。两家公司作为原晨报第一部分中的两个分组，复用A、B等既有选题编号；报告和卡片仍按原三部分及独立选择规则。

1. 读取正式已发布新闻集合和现有提案，按D-ID、原URL、版本和事件去重；上线前接口没有新字段时按既有组织、事件日期筛选，明确功能尚未部署。
2. 官方来源逐一增量检查：ChatGPT／Codex、API更新日志，openai/codex正式版本和OpenAI官方新闻；Claude产品／API更新日志、anthropics/claude-code版本记录和Anthropic官方新闻。官方员工原帖直接读取身份与正文，官方社区嵌入可作有出处的原帖读取方式；其他用户和第三方只作线索。
3. 每天重查最近7日，每周至少一次重查最近30日；第一次补核从11月2日起。每个来源单独保存成功检查位置，失败不推进；不能因其他来源成功而声称全部覆盖。周回查是否完成以实际回执决定，不以星期到来自动盖章。
4. 私密记录置于`output/company-updates/YYYY-MM-DD/`：来源URL、实际开始／检查北京时间、读取方式、原文快照、覆盖窗口、失败／未完成、已有记录／提案关联及通知状态。不存读取令牌。原始时间、发布日期、核对时间分开；历史补录回归原事件日期。
5. 同一事件多来源合并，同版零散修复合并，重大功能可单列；准备「时间—结论—核心论述」双语文案与原始出处、套餐／地区／版本／费用边界。实质更正给出旧文、新文与影响；无变化不提案、不改公共日期。核实的重大安全／价格／弃用变化可单独提醒。
6. 在晨报分列两家的新增、更正、撤回建议，呈现具体可审文案。每家可分别批准，获批部分自主完成。旧具体授权按原提案继续，未批准的新发现不建网站草稿。
7. 获准后沿[内容管理](management.md)保存、英文复核、双端预览、提交复核与明确发布。更正更新同一D-记录正文与摘要，保留原日期；不重复创建事件。发布后回读两专题、首页、HTML／API／MCP及来源，核对实际修订与名单。安全／价格等重大更正另外报告，普通核对不制造新事件。

这些规则不授权自动发表候选或自动部署程序；07:30／08:00是准备与提案时间，不承诺网站定时出现新内容。网络失败保留内部覆盖限制；空增量只代表本站已审集合没变化，不证明官方没有公告。

## AI与读取兼容

- `GET /api/v1/platform/news?company=openai`或`company=anthropic`，以及MCP `curated_news`同名可选参数。省略参数保留全新闻读取，原id／q／revision保持。
- `company_topics`含当前筛选集合的两家ID、数量、月份与产品；条目`company_update`含公司、日期精度、展示时间和导航产品。原title、summary、sources与D-ID仍是正式内容。MCP摘要是有标记的摘录，完整内容跟随reading读取。
- 专题与全新闻共用发布修订，撤回／归属变化在下一次读取时移除。前端复用既有修订检查与撤回清理，普通新增提示应用后保持阅读位置；不声称新增了独立推送或逐次编辑流。
- 旧Codex增量接口、游标和历史归档均保持，本批不创建两家专用同步日程或破坏性协议。

## 验收边界

隔离数据验证3／10上限、分页、同日期排序、未来／无日期／第三方排除、撤回／归属变化、来源日期精度、双语和MCP对等。浏览器验证桌面／390／320px、明暗、筛选直达刷新、详情返回、历史默认折叠及旧链接。首次真实来源检查、连续自然日晨报、首批遗漏内容批准与生产部署分开验收。

原文阅读方式与逐条迁移见[原文阅读与审核](source-reading.md)。v1.20.0本地功能与私密样例不代表线上正文已替换。
