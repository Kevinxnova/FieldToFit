# 资料采集、精选与日常维护

当前精选发布和新页面请先看[平台使用指南](platform.md)。以下保留来源及旧工作流的维护说明。

产品目标按[共享基础 REQ](../product/requirements/foundation.md)执行；本页明确区分**已实现的 beta.2 操作**和**待开发的新精选流程**。检查与更新周期统一 **1 天**。

## 新的内容原则

先维护少量质量足够的对象，起始约 20 个可更少。先确认身份、关注依据、一手来源和材料覆盖，再决定发布。类型可以是模型、工具、Agent、Skill、Harness、重要研究；类型用于辨认，旧领域分类不再承担主导航。

| 来源层次 | 作用与候选来源 | 维护原则 | 自动周期 |
| --- | --- | --- | --- |
| 官方发布与文档 | 模型/Agent/工具作者官网、公告、开发文档 | 提取可核实发布及能力/限制，不把宣传当实测 | 1 天 |
| 作者仓库与发行 | GitHub 关注仓库、提交、发行记录、README、SKILL.md、附属文件 | 固定版本，说明作者身份和实际获取范围；不执行代码 | 1 天 |
| 模型与数据材料 | Hugging Face 模型卡/数据卡、作者官方入口 | 标明上游版本、许可和缺失；不承诺下载全部权重 | 1 天 |
| 论文与研究 | arXiv、OpenReview 公开记录、官方会议/作者页面 | 版本、评审/出版状态分开，保留原文和作者声明 | 1 天 |
| 发现线索 | 现有 RSS、Hacker News、Product Hunt、GitHub Trending、用户反馈等 | 仅辅助发现/关注信号，再核对一手材料；每个启用源单独验证可用性 | 1 天 |

这是目标来源策略，不代表表中所有平台已启用或持续可用。当前配置实际包含论文、官方动态、GitHub、Hugging Face、RSS 与社区适配；具体来源和最近结果应在 `/sources`、`/admin` 核对。历史 19 个默认来源及采集量只代表 [beta.2 记录](../releases/v1.1.0-beta.2.md)。

## 待实现的精选发布流程

发现/更新候选 → 核对对象与变化 → 获取材料 → 整理事实及关注理由 → 审核双端预览 → 发布精选/概览 → 每日复查与纠错。

发布检查：身份及一句话清楚、关注理由可复核、能力/限制有依据或未知、来源和版本/时间可查、材料清单可读且至少一份主要原文可获取。仅转载或宣传页不足时留候选。日检查没有合格内容可以不发新概览；不把原有库整体变成精选。

关注信号注明平台、时间与统计窗口，编辑选择理由单列。来源事实、AI 整理与指定环境下的观察分开；引文匹配只证明文本存在，编辑仍需核查含义。缺失、分歧、过期和撤回遵循[验收规则](../product/acceptance.md)。

原文版本、页面定位、正文/仅链接覆盖和许可边界见[资料契约](../product/data-contract.md)。这些新状态及字段需后续实现，不是当前后台已经具备的完整流程。

## 当前可执行的日处理

`python -m backend.scheduler` 调用 beta.2 知识库日流程：发现来源记录、保存身份/版本、获取可访问原文、整理事实与双语材料、更新简报和适用技术检查。各来源和处理阶段保留状态，所有自动周期为 **1 天**。

历史补采通过管理端安排，分页位置和每日预算影响进度。部分完成时后续继续；“已检查来源”不等于“所有材料已整理”，也不等于新精选已审核发布。限流与网络失败如实保留，不承诺每源每天成功。

## 当前模型配置与降级

新知识库使用 `FIELDTOFIT_MODEL_BASE_URL`、`FIELDTOFIT_MODEL_NAME`、`FIELDTOFIT_MODEL_API_KEY`、`FIELDTOFIT_MODEL_API_STYLE`，支持 `responses` / `chat_completions` 两种接口形式。管理员可保存设置，数据库配置覆盖对应默认值；服务地址、协议和模型名需与实际服务一致。

凭证仅在服务端。未配置时仍可读已有资料和基础查询，生成阶段显示不可用。后续模型只辅助事实提取、翻译与概览草稿，仍需审核；也可人工整理/导入。当前对话中的 GPT 与用户额度不等于部署后的持续 API 服务，不能将它写成后台已配置成功。真实在线验证见 [REQ-O-02](../product/requirements/operations.md#req-o-02)。

旧策展另有 MiniMax、翻译和 Newsletter 配置；修改新知识库模型不代表旧流程已迁移，见[架构](../architecture/README.md)。

## 样本与日常运营

`python -m examples.editorial.load` 显式导入六条短引用与整理样本，不清空现有资料/更正。先在隔离数据库使用；样本不自动成为新精选集合。

每日处理变更、审核、纠错和故障；每周复查精选范围、长期缺失和用户取材反馈。内容修订按对象/期次记录，软件更新按版本记录，两者分开。公开传播展示来源和接入流程，不宣称平台替用户完成了任务。完整执行与指标方案见 [REQ-O-04](../product/requirements/operations.md#req-o-04)。
