# 采集、整理与维护资料

## 日常处理

`python -m backend.scheduler` 调用现行知识库日流程：发现来源记录、保存身份和版本、获取可访问原文、整理事实与双语材料、更新简报和需要复验的检查。所有自动周期为 **1 天**，每个来源和处理阶段保留状态。

默认配置包含论文、官方动态、GitHub、Hugging Face、RSS 和社区发现入口。配置存在不等于来源一直可用；部分来源需要凭证、受到接口限制或可能请求失败。通过 `/sources` 与管理后台查看最近成功、失败说明和积压。

## 事实与整理状态

- 基础档案：身份、来源、时间、版本和可取得的材料；缺失事实保持未知。
- 详细材料：任务需要的事实、局限、文档及原文位置。PDF 提取不保证扫描件、公式和表格结构完整。
- 验证记录：指定版本、输入和环境下的观察结果，不能转移为新版本无条件通过。

来源事实、AI 整理、维护者设计建议和真实运行记录分别标识。引用匹配只证明引文存在，仍需检查解释是否正确。更正或下架通过管理入口进行，保留修改依据和历史。

## 模型配置

新知识库使用 `METIS_MODEL_BASE_URL`、`METIS_MODEL_NAME`、`METIS_MODEL_API_KEY` 与 `METIS_MODEL_API_STYLE`；实现支持 `responses` 或 `chat_completions` 两种接口形式。地址、协议和模型名称应与实际服务一致。管理员也可保存配置，数据库中的设置会覆盖对应默认值。

密钥只在服务端环境中设置。未配置时仍可浏览和基础查询，自动生成阶段会保留不可用状态。现有技术验收没有证明两个在线服务均成功运行，详见 [O-06](../product/requirements.md#o-06)。

旧策展使用 MiniMax、翻译和 Newsletter 的独立配置；这部分调用关系见 [架构](../architecture/README.md)。不要把新知识库的配置修改理解为旧流程已完成模型迁移。

## 样本与补采

`python -m examples.editorial.load` 只显式导入六条仓库样本，保留短引用，已有资料和更正不会被当作默认种子清空。先用隔离数据库检查再用于自己的环境。

历史补采通过管理端安排，分页位置和每日预算会影响完成进度。日任务返回部分完成时，后续继续处理；不能把“已检查来源”显示为“所有材料已整理”。
