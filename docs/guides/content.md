# 资料采集、精选与日常维护

FieldToFit v1.0.0 · 2026-09-11。已有 27 项公开对象；完整操作见[平台指南](platform.md)与[运行方案](operating-model.md)。P2 具体首发内容在[待确认清单](../product/launch-selection.md)，未自动发布。

## 内容范围

两条线：重点公司/产品的动态，以及近期受关注、长期有价值的精选资源。本期重点从两者提炼，来源观点分点，FieldToFit 评价独立。每天不设发布条数，入选看具体内容与证据。

| 来源层次 | 用途 | 处理规则 | 检查周期 |
| --- | --- | --- | --- |
| 公司/团队官方公告、文档 | 跟踪 OpenAI、Anthropic、Google、智谱、DeepSeek、Qwen、MiniMax、字节 Seed/豆包等 | 关联公司、产品、版本和事件，明确开放条件与来源日期 | 1 天 |
| 作者仓库与发行记录 | 模型、工具、Agent、Skill、Harness 及开源项目的正文 | 固定版本、读取 README/文档/许可；不执行来源代码 | 1 天 |
| Hugging Face / 论文与研究 | 模型卡、数据卡、论文及关联实现 | 开放权重不等于无需核查许可；论文版本和作者声明分开 | 1 天 |
| GitHub Trending、Hacker News、Product Hunt、RSS、用户提交 | 发现线索与关注依据 | 信号记录来源/窗口/观察时间，事实回到一手材料 | 1 天 |

以上是目标范围，不能据此宣称每家公司已经接通自动采集。网站的两张跟踪说明表仍待开发；实际覆盖以配置及成功日志为准。

## 当前更新流程

`python -m backend.scheduler` 执行一次 `platform_maintenance.run_daily`；`--daemon` 每 1 天再执行。Vercel 当前只登记 `/api/cron/platform` 每日调度。不要重复启用多套写入同一库的调度。

当前链路：登记来源 → 抓取/识别变化 → 候选与材料快照 → 导出整理待办 → AI 或人工整理 → 导入草稿、核对引文 → 审核发布 → 双端读取同一修订。已实现草稿与发布隔离、变更复核及撤回；新增 P2 事件关系和分点评价仍待适配。

## 本地 AI 整理与网站运行

服务器负责有预算的原始采集与公开读取，本地 AI 可以阅读导出的真实材料，整理中文介绍、事实、限制和关注理由，然后交回草稿。现有 `scripts/maintenance/prepare_editorial.py` 将人工/AI 整理笔记绑定到实际 intake 快照并检查引文。完整命令、鉴权与审核步骤见[运行方案](operating-model.md)。

当前对话中的 GPT 可完成本次整理工作，不代表服务器拥有一个自动运行的 GPT API。若后续需要无人值守整理，应另配可调用模型服务并验收；无需为了公开读取强行配置生成模型。已有 FIELDTOFIT_MODEL_* 配置仅用于相应整理流程，凭据不进入公开资料。

## 发布与维护准则

- 具体名单确认后，逐条核对身份、版本、来源时间、事实/限制、可读主要材料及收录理由。仅有宣传或转载时留候选。
- 来源事实、作者声称、编辑评价和实际测试分别标识；关注度不是能力排名，文章日期不是模型首次发布日期。
- 一天没有合格新增保留上一期真实时间；采集失败单列，不能用“无新内容”覆盖错误。
- 每周复查关注范围、长期缺失、旧版本与纠错；软件更新写 CHANGELOG，内容变更写对象修订/期次。
- 连续 3 个真实日周期、生产维护写入/恢复、用户取材效果仍按[REQ](../product/requirements.md)验收，不能用本地模拟记录替代。

旧策展与 Newsletter 留作兼容，相关脚本可能写实际数据库；本轮文件整理未运行。示例导入不自动成为精选，案例继续 pending。
