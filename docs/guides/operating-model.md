# 正式版运行与内容更新方案

适用于统一内容管理上线后的 FieldToFit；当前版本见[更新记录](../../CHANGELOG.md)。当前采用 Vercel + Turso，正式地址 [fieldtofit.top](https://fieldtofit.top)。软件上线与真实持续运营分别验收。

## 从来源到两个页面

| 环节 | 当前做法 | 边界 |
| --- | --- | --- |
| 发现 | 官方来源、GitHub/Hugging Face、RSS、论文及社区渠道按现有配置采集；结果进入旧 tools 或资料库 | 不把配置存在当作采集成功；显示真实失败和时间 |
| 每日审阅 | 同一后台汇总候选，按北京时间的本站发现日及来源/类型/状态分页筛选 | 来源发布日期独立；选择候选不直接上线 |
| 待整理 | 指定新建动态/持续关注，或关联已有内容；附上已有来源材料 | 只有摘要时明确标记，不能称为完整原文 |
| AI 辅助 | 编辑页导出草稿与材料，本地 AI 整理后导回 | 只保存草稿；不使用个人登录凭据作为网站 API；不自动调用模型 |
| 人工审核 | 整理介绍、版本表、观点、出处与缺口；预览 For you 和 For your AI | 旧预览、过期材料指纹、无效字段不能发布；人工仍须核实内容含义 |
| 发布 | 明确确认并填写原因，事务写入数据库共享集合 | 两端及现有 curated_news / curated_watch 同源；内部备注不输出 |
| 更正 | 下架或恢复历史到草稿，核对后再发布 | 历史保留，恢复不自动上线；数据库故障不冒用旧文件 |
| 反馈 | 分页处理网站反馈，推荐登记为候选，备注可关联内容编号 | 邮箱和 GitHub 手工登记，无自动发送、同步或用户回执 |

## 每天检查，按审核发布

服务器现有 cron 每天 02:00 UTC（北京时间 10:00）调用 `/api/cron/platform`；旧任务路由保留兼容，不重复调度。已维护仓库的正文变化、来源可用性及图表源检查保留真实记录。没有变化不重复发布，材料获取失败也不把旧日期刷新为今天。

每日优先处理重要更新、失败与待整理事项；每周检查名单、失效链接、投稿和反馈。连续三个真实日周期、完整来源覆盖与首批真实投稿仍需要运营记录证明，测试不能替代这些证据。

当前已发布内容不依赖在线模型读取。电脑离线或额度不可用时，服务器采集可以继续，草稿等待整理，公开版保持可读。尚未启用本机无人值守整理或自动发布；服务器持续整理如需另配模型服务及预算，应另行对齐。

图表保留 AA/Arena 不同坐标和来源口径；维护者在内容库核对数值、日期、配置与旗舰名单后发布。每日网页可用性成功不意味着评分已更新。完整原文覆盖、主体/产品/事件关系与自动变化归并仍有后续工作。

## 数据与部署

公开页面、MCP 与后台运行在 Vercel，数据保存在 Turso。已发布动态/持续关注/图表迁入共享内容集合；仓库 JSON 保留为首次导入、审阅与历史基线。后台保存草稿不会改变线上，发布后也不需要重新部署网页。

应用版本以实际运行服务为准，所有有修改的交付提交按版本规则记录；数据库内容修订另有即时历史、时间与原因。定期导出公开内容用于版本归档时，不把私密后台备份放入 GitHub。

部署流程：隔离开发与验收 → 私密数据库完整快照与恢复完整性检查 → 部署兼容代码 → 首次显式迁移 → 核对三个公共集合原样一致 → 管理登录及只读 MCP 检查。管理权限、定时密钥与可选读取凭证独立。具体操作见[内容管理](management.md)、[部署](deployment.md)与[版本规则](releasing.md)。

全库恢复先在隔离环境验证，再恢复数据和匹配代码。旧 v1.0.5 忽略数据库中的新内容，因此迁移后不能仅回滚旧代码。Cloudflare 可后续评估为域名/缓存层，但管理接口和 MCP 不应进入公开缓存或被浏览器验证码阻断。本版不更换部署平台。
