# 热点信息卡维护

需求与范围以[REQ-6-22](../../FieldToFit-PM.md#hot-information-cards-plan)为准。信息卡是同一条D-动态的人工解读与分享版本，首页位于本期速览下方。原动态ID、官方证据和历史继续保留；「热点」表示编辑精选，不是实测热度榜。

## 镭射收藏样式

2026-10-12所有者选定镭射收藏卡，v1.8.40按最新反馈取消旋转：三张精选平放，保留渐变边框、关键变化图形区与官方证据入口。图形区直接读取已审首项变化标题，不另维护宣传文案。

默认收起「对谁有用 · 本站判断」与「先看条件」，鼠标移入对应卡片或键盘聚焦时展开，离开后收起；Escape可收起。明确的「展开／收起人群与条件」按钮支持触屏，触控高度至少44px，展开状态与内容关联提供给辅助技术。显式展开后保留，直到点击收起；官方证据、完整阅读链接和待更新提示始终可见。展开单张时相邻卡片保持自身高度。

保留600ms上浮8px、1.04倍放大及随指针移动的反光，卡面不旋转。触屏、阅读区域不足600px和减少动态效果模式不播放这些动效，展开功能仍可用。关键变化图形区96–140px，标题18–26px，正文13px。

按阅读区域宽度排版，至少600px时一排三张，较窄时单列、单卡最多560px。三列利用两侧各18px留白及12–16px间距增加卡宽；桌面目录缩至170px、间距24px，901–1100px目录继续收为按钮。手机不使用两侧扩展。完整文字不裁切、不设固定卡高。当前证据见[按需展开验收](../validation/2026-10-12-hot-card-disclosure.md)，此前布局与交互见[三列布局](../validation/2026-10-12-hot-card-layout.md)及[转正放大](../validation/2026-10-12-hot-card-presentation.md)。

效果使用本站独立实现的CSS与指针处理，无新增组件库、网络素材、自动播放或持续后台动画。参考方向为[React Bits Holo Card](https://reactbits.dev/components/holo-card)，未复制其源码。完整详情与人工PNG继续静态分层阅读，原图片指纹与内容修订规则不变。实际验证见[镭射样式验收](../validation/2026-10-12-hot-card-motion.md)。

## 每日提案与选择

2026-10-17所有者已确认[REQ-6-34／REQ-11-6](../../FieldToFit-PM.md#hot-information-cards-plan)。沿用同一07:30准备／08:00交付安排、原收件对话与通知；日报第三部分固定为「热点信息卡｜今日推荐与旧卡维护」，前两部分保持完整。

每天主推一张，有足够价值时最多三张，不凑数。优先当日主流模型／产品的重要能力、功能、价格、开放方式和采用条件变化；普通修复只有明显影响使用才推荐。先表列卡1／2／3、关联动态／档案、读者价值、建议首页位置及移出对象，再逐张交付完整拟上卡文案、图面预览、三项变化、两类人群、限制、下一步、官方原文定位、版本、真实日期与未实测范围。准备阶段可先做中文全稿及图面预览，选定后完成正式已审中英PNG。

每日读取完整公开信息卡与首页三张名单，逐卡记录保留、建议替换、需要更正、检查失败或未完成。使用只读交接脚本 `scripts/maintenance/hot_information_cards.py --day YYYY-MM-DD --output output/briefings/YYYY-MM-DD-hot-cards.json` 保存当前内容、证据指纹及实际覆盖；`--checks` 仅接纳具有当前卡片证据指纹、实际时间、具体理由和来源的人工核对记录，不自动判断无变化。未提交检查的卡明确未完成；无新增或失败仍交付第三部分。证据留在已忽略私密目录，提案沿用当天私密批次，不以脚本导出冒充后台审核或送达。私密卡片提案使用`proposal.type=hot_card`及完整`proposal.card`（含PROSE字段）；服务器为事件版本加`hot-card:`区分原动态决定。普通动态先发布而卡片尚未上站时，不把卡片决定误记已发布；只有实际发布文案与该卡提案一致才回写完成。

卡1／2／3明确选择即授权该卡中英整理、分享图、预览验证、发布及必要部署；不用重复批准同一张全文。普通动态全部发布、报告选择和卡片选择分别处理，可一次回复「A–J全部发布，报告1，卡1」。未选卡只存私密提案；配置或开发确认不授权发表具体新卡。功能未正式部署时只读旧rank汇总并报告缺口，不能假称新原子轮换已上线。

## 内容与人工制作

后台「热点信息卡」维护结论、范围、三项变化、两类人群、1–5项采用条件、一条下一步、官方证据和验证边界。人群场景及行动建议分别标为本站判断／建议，不冒充官方实测。中文约350–450字；英文对应相同事实，允许长图高度不同，不以缩小文字强行同高。

人工完成全部文案与排版。使用1080px宽PNG，二维码指向 `https://fieldtofit.top/news/D-ID#hot-information-card`；英文使用 `/en/news/D-ID#hot-information-card`。图内保留来源、事件日期、修订日、核对日和未实测范围。上线前从最终PNG实际解码二维码，检查手机阅读及下载落盘。

本轮三个样稿在[双语文案](../../tests/fixtures/hot-card-copy.json)和[完整隔离样本](../../tests/fixtures/hot-cards.json)中；完整隔离样本仅用于验证，不整条导入正式数据库或覆盖原正文。2026-10-13按所有者明确授权，从三个既有已发布动态逐条补充已预览的hot_card与双语审核，经预览后正式发布；原正文、来源和事件日期保持。六张人工PNG在 `frontend/public/hot-cards/`，文件清单为 `backend/knowledge/content/hot-card-assets.json`。后续独立事件需重新选题，不机械复制样稿。

## 图片登记与发布

动态的可选 `hot_card` 字段随原有草稿保存、导入导出、双语预览、发布与历史流转。维护者人工登记资源，产品端不生成图片：

- `featured_rank` 为0（仅详情和历史）或1–3（首页顺序）。新卡首次发布带首页标记时进入首位，超额旧卡原子移到索引；既有卡普通修改保持当前位置。首页名单与新卡发布在同一事务更新，无须先取消旧卡。显式手工位置调整仍通过同一审核门槛；只改位置不伪造精选时间。
- `publication.hot_card_first_published_at` 与 `hot_card_selected_at` 由服务器真实发布生成；旧卡无记录则不补造；首次接入沿既有已审位置作基线，此后按新卡真实上站轮换，不拿动态原始发布日期推算卡片先后。`hot_card_selection.ids` 在过滤、分页前生成，网页、阅读和MCP复用；历史列表不截断。
- 发布返回 `hot_card_rotation` 的before／after／entered／left／index_only；预览只提供预计变化，不能算上站。发布回执丢失先核对公开名单、版本和历史，禁止盲目重试。其他卡仅更新精选位置及相同译文绑定，私密改稿继续保留且旧预览失效。
- `evidence` 必须引用该动态已有的来源编号，并提供原文定位。
- `revised_at` 是卡片实质修订日，`checked_at` 是图中这次证据核对日。例行可达性检查沿用独立检查台账，不改卡片日期。事件日期仍由原动态提供。
- `share.content_revision` 使用 `backend.knowledge.hot_cards.fingerprint(item, card)` 计算，绑定对象、核心文案、来源、日期。图片资源含独立中英URL和SHA-256；英文还登记同一函数对已审英文投影计算的 `text_revision`。修改文字或英文翻译后，旧图片绑定失效。
- 人工核对图片后，将URL、SHA-256、D-ID、文案指纹和英文指纹登记至同一资源清单，再在后台图片登记区／既有导入文件关联。重新排版用新的资源文件名，不能覆盖已转发旧图。预览检查已登记的文件与指纹；本地同时检查实际字节。服务器无静态目录时依据随代码交付的清单校验，静态文件另由网站托管。
- 中英文审核、双端预览和明确发布后，首页、详情、HTTP及MCP读取同一对象。资源需先随应用部署可访问，再按授权发布对应内容。仅部署代码不会自动发布样稿。

公开详情和图片保存不要求注册。查看图片使用可关闭弹窗；微信内可以长按图片保存。下载会核对图片字节，失败提示重试，正文仍可读。

## 更正、轮换与撤回

同一事件的条件变化修订原卡；新事件建立新D-记录。已知事实待更新时，在原卡设置 `needs_update` 和公开说明，经原审核流程发布后暂停分享下载，保留旧事实的时间与说明。无需为了暂停下载重新制作旧图；完成更正与新图后再恢复为 `current`。

只改变精选位置／图片排版不刷新原动态的发布修订时间；核心事实、公开更正说明和维护状态变化会形成真实内容修订。下架原动态后首页、历史筛选与详情同步撤下，接口不泄漏草稿。已保存的旧PNG无法收回；二维码稳定详情反映现况或下架状态，静态旧文件不是持续有效承诺。
