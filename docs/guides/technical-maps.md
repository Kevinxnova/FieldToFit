# 技术演化地图的整理与维护

开发、证据与网站状态仅由 [REQ-22](../../FieldToFit-PM.md#req-22) 管理。v1.8.7是在现有近期动态、审核与修订流程中增加技术地图投影，保留news/watch/charts三个内容库，不另建发布库。

## 放置与内容

For you 顺序为本期速览、技术演化地图、Codex 28天进化日志、发布与更新。近期入口展示最多三张含近30日报告或实质修订的地图；`/maps`支持问题搜索、近期与历史索引。每张地图使用稳定的`/maps/<slug>`，相关档案与For your AI同时提供入口。

一个技术问题对应一个news条目与唯一slug，新报告加入这个问题的reports/nodes/edges；建立后不能更名或由其他条目占用。通过现有下架动作撤回，恢复仍须重新预览发布。已认可的首张案例是D-90「V4 → V4.1：Agent 的成本省在哪里？」；来源是2026-09-17的[作者报告v1](https://arxiv.org/html/2609.19969v1)，没有独立复现声明。此前Qwen／旧报告示意不进入发布内容。

节点分别登记机制、实验条件／配置、结果、局限和原始报告位置。数值须有单位、比较基线及条件；关系区分inheritance（方法继承／纳入）、baseline（基线比较）、parallel（并行探索），每条关系都有出处。继承关系不允许循环，孤立节点及失效引用不能通过预览。

报告首次日期与报告修订日期分开，实质修订须说明新增方法、实验或更正；排版、文字调整不使旧报告进入近期。地图首次发表／最近修订由发布流程维护，不从报告日期或检查日期推造。种子导入只有历史基线，不能把导入时间说成首次发表。

## 每日与每周

07:30本地助手获取维护交接，读取报告正文与版本，检查原入口的变化。每个北京时间自然日最多处理10份不同报告，按最久未检查轮转；失败记录保留上次正文指纹、成功时间与日期证据。时间戳存UTC，排期及当天判断用独立北京时间日期。摘要和搜索结果不能代替报告全文；潜在arXiv修订先标为待核对，不自动判为实质修订。

检查输入为列表，每项含url、当前check_version对应的version、status。read需实际body、first_published_at、revised_at、report_version、locator、note及change_kind；变化类型为baseline／unchanged／cosmetic／method／experiment／correction，失败为failed及error。已有正文改变时不能再写baseline或unchanged。每次检查使用版本冲突保护。CLI输出权限为0600，凭据与报告正文不打印。

08:00只交付具体提案：content为完整news文案与technical_map，base_revision为当前地图修订（新问题为null），reason为具体价值。须当天读过报告，报告日期／版本与检查一致；新地图至少有近30日报告或实质修订。已有问题附字段前后变化，重复问题须回到原slug。相同提案沿用既有不重复提醒与稍后／不采用决定，检查和提案不自动创建草稿或发布。

每周一交接列出已有问题、历史地图、待决定与积压；助手据此提出合并重复问题、补齐方法关系及处理积压的建议，不自动合并。每周1–2张新图或深度更新是目标，缺少可靠材料时留空。历史问题继续检查、更正与维护，不删入口。真正的晨间准点、连续自然日及周整理效果须上线后验收。

## 审核与公开读取

后台「每日审阅→技术地图维护」查看检查与缺口；建议进入「更新批次」。主人确认继续后，关联原news条目，明确点击「将已确认地图方案填入草稿并预览」。填入时再次检查决定版本、目标、公开修订和草稿版本，防止覆盖新决定或修改。新问题须先将已认可原始材料注册候选，再关联新增news；来源候选已有时直接沿用。

地图编辑器直接填写报告日期、方法、配置和指标，按已登记的来源与节点名称选择依据和关系。共用的高级JSON导入仍需明确应用，未应用输入不能保存或发布。预览检查引用、单位、配置、日期、唯一身份与关系，再确认两端预览、填写内部理由和发布。公开change_summary是读者可见的修订说明；内部发布理由、原始私密检查与失败信息不进入地图。

只读接口为`/api/v1/platform/maps`及`/<slug>/history`、`/<slug>/compare`。通用精选MCP增加curated_maps，与网页使用同一节点、关系、指标、日期及出处投影，可带revision检查过期。网页可复制稳定链接或完整图结构给AI。公开历史只读取import／publish，导入基线单列；恢复草稿不制造公开历史，撤回后详情、历史、对照与站点地图同步停止公开读取。

地图和关联档案提供无脚本正文、原文位置与正确canonical；预览环境仍不被索引。公开页面无缓存；管理员鉴权与只读访问保持隔离。

## 部署前后

先备份，执行现有`/admin/workspace/upgrade`增加两张私密检查表并幂等注册研究入口。已有已审数据库优先于种子文件，升级不会替换生产动态，也不会自动发布D-90。发布首张认可案例时，从批准的材料候选创建news草稿（生产当前最大D-89时为D-90），再按现有预览／发布步骤交付。完成正式网页／MCP核对后，才接上晨间自动任务并开始真实自然日验收。


## 报告阅读形式与整理规则

<a id="report-reading"></a>

v1.8.17将已对齐的形式保存为可选`technical_map.reading`，随既有news草稿／预览／发布／修订保存，仍只有一个发布集合。没有reading的旧地图直接使用原节点结构，不在运行时生成正文。

阅读顺序固定为：居中问题标题 → 路线全貌与短解释 → 编号核心结论 → 同编号、同标题的展开论述 → FieldToFit判断 → 来源与修订。路线点选只改变解释与高亮，不隐藏正文或自动跳到报告；明确点击阅读链接才定位。结论定位相应论述，论述返回结论或对应路线，`#argument-<finding-id>`可分享。手机保留全部连线并可横向查看路线，正文纵向阅读；密集原图可以放大，关键数值同时写在正文里。

每份报告优先整理3–5个真正影响理解的观点，不凑固定数目。结论标题表达观点，而不是「方法／评测／结果」栏目名；对应论述自动复用标题与编号。有多个并列观点、条件或读图要点时使用原生有序列表，单一解释用自然段。作者结果、样本／全量、估计费用与实际报告费用分别注明；编辑判断单列。重点只标少量影响判断的句子，使用作者结论／关键证据／适用边界标签与柔和底色。

后台地图编辑器启用「图文报告阅读形式」，填写阅读标题及各核心观点，关联已有节点与报告位置，再添加段落、编号分点、重点标记或原图块。观点及论述块可上移；编号和展开标题自动同步，避免两套文本漂移。草稿保存后公开内容不变，必须核对人读与AI双端预览后发布。只调整读法不修改报告首次日期，也不标记为报告实质修订。

字段约定：reading含title、findings与editorial；每个finding含稳定id、title、summary、node_ids、evidence、blocks。paragraph用text；points用items；highlight用text与claim／evidence／limit标签；figure登记image_url、alt、caption、attribution、license、evidence。正文限定文本，不接收HTML。每条结论引用原始报告并关联真实节点，图表只能使用已核对的静态PNG；无效引用、重复编号、空论述、未知资源或不匹配的许可／来源不能通过预览。reading变化纳入公开历史及前后对照，HTTP和curated_maps携带同一字段，无脚本页面也保留完整结论、论述、图表和来源。

原图接入时，从已许可的原报告截取图表，保留坐标、单位、图例和图注，只裁周边空白。PNG存于frontend/public/report-figures，登记backend/knowledge/content/report-figures.json中的SHA-256、版本、原始来源和许可，随应用部署；内容块注明作者署名、图号／页码和版本，替代文字给出读图重点，并提供原页定位和完整图片。新增资源须随应用提交验证，不能仅在后台填写一个不存在的路径。图片不加载时替代文字、图题、正文关键数值与来源仍可读；不能给原图重画数字或把高亮改进图内。

Agent in a Bottle的已对齐参考文案保存为backend/knowledge/content/map-reading-bottle.json，用于可复用格式及隔离验收；它不会自动导入或发布。正式内容沿用已有reusable-agent-artifacts／D-103，并保留首次发表历史。原图2同时支持观点1／3，按报告同一证据理解，不计为独立实验。后续新报告仍按具体提案与主人对齐，不因这次部署授权自动发布。
