## 每日采集

部署配置为每天北京时间 06:30（UTC 22:30），所有来源间隔为 1 天。它与本地 08:00 选题安排是两件事：服务器产生私密发现材料，本地助手搜索补充、核对已有内容并提出具体文案。改动部署配置后，需真实部署和执行才能证明生产定时已生效。

单次日流程最多并行检查三个来源，整体预算 180 秒；每个来源还受剩余预算和单源超时限制。按北京时间自然日领取检查任务，避免执行时间略有漂移就漏掉一天；管理员立即检查可显式重试。

采集有条数与时间上限，不能把一次执行称为搜完所有信息。模型和 GitHub 检查新页并继续旧分页；官方订阅／列表保留未完成条目与已处理签名；论文沿保存的偏移续跑。默认查看近期约一周并留出重叠窗口。未读完分页标为待续跑，失败与限流不标成功；已经取得的材料先保存，后续请求失败不丢掉它们。

材料保存原始 URL、上游日期、发现及读取时间、覆盖程度、内容哈希和修订。来源仅给日期时保留日期，不补造时分秒；未知日期不以发现时间代替。正文读取失败时保留真实摘要及缺口，已有正文保留原获取时间。模型卡或 README 缺失标为未完成；已知失败的旧模型卡不会仅因日期较早而跳过重试。仅指标变化不伪装成内容更新。网络地址安全检查仍然生效，不为让来源通过而放开内网抓取。

## 每日审阅怎么用

1. 先看今日新增、优先查看、待整理、来源异常与已有内容关联计数。默认“优先查看”覆盖未处理的跨日候选，避免只看今天而丢掉昨日重要项。
2. 切换“值得关注”“待核实”或“全部发现”，可以按时间、日期、来源、类型和状态查看。翻页覆盖所有符合筛选条件的结果。
3. 打开条目查看推荐原因、未知项、带日期的关注快照，以及已获取原文。原文是私密候选材料，不会自动进入公开 MCP。
4. 如需调整优先级，填写具体理由；重新计算不会覆盖人工决定，也可恢复自动判断。旧候选可每批重新评估 100 条。
5. “加入待整理”保留在跨日队列，并创建或关联私密草稿。它不更新 For you / For your AI。具体内容与用户对齐、整理和双端预览后，才进入既有明确发布流程。

### 排序依据

| 分组 | 判定原则 |
| --- | --- |
| 优先查看 | 已获取可核对的作者／官方完整材料，并有近期发布、模型修订、仓库变化、可尝试入口或实际关注增量等依据；低 Star 项目也能进入 |
| 值得关注 | 有原始材料但完整性、时效或优先理由不足；旧正文未重新获取时明确提示，归档项目降入此组 |
| 待核实 | 只有讨论、指标、链接，或原始出处无法确认；高累计 Star 不足以越过原文门槛 |

这是一组可解释的审阅规则，不是 AI 能力评分或全文事实核验。完整材料判断使用正文覆盖和最低长度，使用入口判断依据安装／使用说明；最终内容质量仍需阅读和核对。当前规则将约两日内至少 50 个新增 Star 作为可选关注提示，必须来自同一来源两次实际观测；累计 Star、点赞、下载等单次快照不冒充增长。没有指标写未知，不按零关注处理。

同 URL、同修订合并发现出处，不同版本保留；这不等于已实现跨链接、跨对象的同一事件语义归并。跨日提醒账本和“继续／稍后／不采用”批次决定记录属于后续 REQ，不能以本批筛选界面代替。

## 数据、部署与回退

新增四张私密表保存发现、出处、指标观测和优先级；初始化建表与来源注册幂等，已有来源管理员设置不会被重复播种覆盖。现有管理员权限和请求校验继续适用。后台私密备份包含新增表；数据库、备份与候选正文不提交 GitHub。

部署前备份，部署后核对实际版本、来源表、管理员只读状态及日流程。公开动态、持续关注和图表不因采集自动更改。回退应用时保留数据库中已经发布的内容和新增私密记录，不用旧种子覆盖，详见[内容管理指南](management.md)。完整备份恢复与连续三个真实日周期需独立验收。

Kimi 使用当前研究列表，不使用停在旧年份的开放平台旧日志。Qwen 从官网研究页实际调用的 `/api/v2/article/retrieval?type=qwen_ai&language=zh-CN` 读取公开正文，忽略其中内部元数据链接；响应上限 8 MB，正文按每日预算分批入库。Seed 从官方页面嵌入的 JSON 读取文章路径，不执行脚本。两者入口变化会报失败，不能空页面记成功。

更新日志/产品页正文即使 URL 不变也计算内容指纹；索引定期复查旧发布日期文章，队列完成一轮后重新循环。变化前材料保存在私密历史，管理员候选详情最多展示最近十次；仅检查未变化不发布。页面核对时间不当作条目发布日期。豆包客户端、火山与百炼服务公告、MiMo 独立 API 日志仍是明确缺口。
